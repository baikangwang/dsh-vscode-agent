## §2 八面逐项证据

### 面 1：CLI 入口/参数 —— 一致 ✅

- alpha.4：`apps/cli/package.json` bin `dsh = lib/bin.js`、版本 0.1.2-alpha.4；`apps/cli/src/args.ts` `web` = `--profile web` 别名；`packages/bundle/web-app/src/startup.ts` web 参数族 `--host/--no-open/--port/--trusted-host`，`--host 0.0.0.0` 显式拒绝、`--port` 必须数字。
- 扩展锚点：`src/dshProcess.ts` spawn argv `node <binJs> web --host 127.0.0.1 --port N --no-open` —— 与 web 参数族逐字吻合（`--trusted-host` 为新增可选，不传即默认行为）。
- 环境处理：`apps/cli/src/profile-boot.ts` L66-71 注释明言 `$DSH_HOME` 为 launcher/test 在 import 后设置的注入点，`homePatchPath()` 经 `resolveDshHome()` 消费 —— 扩展的 `DSH_HOME` spawn 环境注入契约不变。内部参数经 `provideCmdline`（L258-262）以 `ctx.cmdlineArgs` 快照传入树内，与 `startup.ts` 读取方式一致。
- 新增（增量）：`DSH_TELEMETRY_DISABLED` 环境开关（L77/L100-103/L170，任意非空值禁用会话遥测）—— 可选加固旋钮，扩展不设置亦不受影响。

### 面 2：端口/就绪横幅 —— 一致 ✅

- alpha.4：`packages/bundle/web-app/src/index.ts` L80 `LOOPBACK_HOST='127.0.0.1'`；L158-162 `localWebUrl()` 产出 `http://127.0.0.1:<port>`；L268-281 `announceReady()` 横幅 L280 `console.log(\`dsh web: ${authenticatedUrl}(LAN: ...)\`)`；`browser-auth.ts` L223-230 `authenticatedUrl()` 将 pathname 重置 `/`、清空 search/hash 后 `searchParams.set('token', launchToken)` → 横幅精确形态 `dsh web: http://127.0.0.1:<port>/?token=<43位base64url>`（e2e `apps/cli/tests/web-auth.e2e.ts` L166 正则 `^[A-Za-z0-9_-]{43}$` 佐证令牌字符集与长度）。
- 扩展锚点：`src/dshProcess.ts` URL_RE `dsh web:\s+(http:\/\/127\.0\.0\.1:(\d+))` + TOKEN_RE `?token=([A-Za-z0-9_-]+)(?=\s|$)` —— 与 L280 产出逐段匹配；e2e L94 横幅正则 `/dsh web: (http:\/\/[^\s]+)/u` 独立佐证。
- 备注：横幅 URL 恒以 `127.0.0.1` 打印（`localWebUrl` 硬编码），即便用户新增 `$DSH_HOME/cordis.patch.yml` 家庭层覆盖 webserver host，横幅解析仍健壮；LAN 段仅作扩展展示，不影响判定。

### 面 3：`__DSH_BOOT__` 注入 + iframe/CSP —— 一致（增量兼容）✅

- alpha.4：注入改为结构化 `IndexInjection` 行——`packages/client/modules/src/index.ts` L522 `rows.push({kind:'global', name:'__DSH_BOOT__', value:graph})`；`packages/host/webserver/src/injections.ts` L86 新增 `__DSH_BOOT_READY__` deferred tail 行。
- 扩展锚点：探活判据为 `text.includes('__DSH_BOOT__')` —— 结构化行仍携带该全局名，substring 判据天然兼容；`__DSH_BOOT_READY__` 为纯增量，不参与扩展判据。
- 框架阻断排查：`packages/host/webserver/src`、`packages/host/frontend-static/src`、`packages/client/connection/src` 三包**零** `X-Frame-Options`/`frame-ancestors`/`Content-Security-Policy`/`Cross-Origin` 头命中；frontend-static 亦无 `<meta>` CSP 命中 —— iframe 嵌入不受阻。
- 路由范围：`API_PATH='/api'`（api-path.ts）前缀路由；`rpc-host.ts` L96-98 拒绝序 = 信任防护 403 → cookie 401（正文 `'dsh web authentication required; reopen the URL printed by dsh web.\n'`）；`REMOTE_STREAM_MUX_PATH='/api/remote.mux'` 升级路由精确路径注册（webserver index L175-185/L257-280）；`frontend-static` 仅索引页受 `authorizeIndex`，静态资源与 `/plugins` 公共 —— 与 `src/authProxy.ts` R1-R10（Host+Origin 重写、剥离 Set-Cookie、WS 原始 TCP 转发）及 401 偏差检测假设一致。

### 面 4：token 认证与本地代理协议 —— 一致 ✅

- alpha.4：`packages/client/connection/src/browser-auth.ts`（313 行）常量与 alpha.2 基线逐项相同：`COOKIE_PREFIX='dsh-auth-'`、`PAYLOAD_VERSION=1`、`SECRET_BYTES=32`、`TOKEN_QUERY='token'`、凭据键 `credentialKey('client-connection','browser-session')`；cookie `v1.<body>.<sig>` HMAC-SHA256、30 天最大生命周期（`connection/src/index.ts` L88 `cookieMaxAgeDays` 默认 30；`web-app/cordis.patch.yml` connection 行仅注入 `trustedHosts`，**无** cookieMaxAgeDays 覆盖）；信任防护（`api-request-trust.ts`，118 行）Host 环 → `sec-fetch-site` → Origin 校验顺序不变，403 先于 401。
- 凭据：`packages/credentials/credentials-local/src/index.ts` `DOCUMENT_VERSION=1`、顶层键 `version/refs/records`、grant 记录 `{kind:'grant', payload:{version:1, secret}}` —— 与扩展 `readCredentialsSecret` 缩进遍历解析（records@0 → key@2 → payload@4 → secret@6）兼容；POSIX 0600（Windows 无涉）。
- e2e 佐证（`web-auth.e2e.ts`）：L168-171 伪造 Host（localhost≠127.0.0.1）→ 401（authority 绑定生效）；L173-181 `GET /?token=` → 303 + `Set-Cookie`（HttpOnly、SameSite=Strict、非 Secure）；L183-190 cookie 携带访问 `/api` → 200；L194-197 **每次启动令牌重新生成**、跨重启旧 cookie 依然 200（secret 持久化生效）—— 与扩展三态探测器（bare 200+BOOT / token-303 / cookie 200+BOOT）及 authProxy T/C 双路径判定完全对齐。
- 主目录：`packages/util/home-paths/src/index.ts` L87-91 优先级 配置 > `$DSH_HOME` > `~/.dsh` 不变。

### 面 5：外部实例接管 —— 一致 ✅

- alpha.4 托管启动命令行形态不变：`node <...@deepseek-ai/dsh/lib/bin.js> web --host 127.0.0.1 --port N --no-open`；`web` 别名范围（args.ts）与 alpha.2 相同。

- 备注：`--profile web` 字面规则仅对显式 profile 写法命中（alpha.2 时代即如此，非本轮回归）。

### 面 6：数据目录边界 —— 一致 ✅

- alpha.4：dsh 侧数据（会话、凭据 `$DSH_HOME/.credentials.yaml`、profile 目录）全部锚定 `DSH_HOME`（默认 `~/.dsh`）；无新增越界目录。

### 面 7：Web UI 面（面板协议/静态服务）—— 一致 ✅

- 面板上行白名单（`src/panelMessages.ts`）、详情卡动作（`src/webviewDetails.ts`）、iframe CSP（`src/webviewHtml.ts` `frame-src http://127.0.0.1:*`）均为扩展内部契约，不依赖 dsh Web UI DOM —— Web UI 侧变更仅经 URL/iframe 表面化，已被面 2/3 覆盖。

## §4 决策记录

1. **不发起适配轮**：8/8 面证据表明 alpha.4 对 v0.1.16 无破坏；按"不破坏则不设版本轮"原则，0.1.17 不因本调研产生代码改动。

## §5 风险与观察点（均非阻塞）

1. **npm alpha 领先验证锚**：线上 `alpha=0.1.2-alpha.5` 比本次源码锚（0.1.2-alpha.4 @ 4e84901e）新一个补丁位；按"源码为事实基准"策略声明差异，扩展下次 24h 新鲜度窗口自动拉取 alpha.5 后建议按本报告同法抽查增量。
2. **`$DSH_HOME/cordis.patch.yml` 家庭层**（profile-boot.ts 新增语义）：用户可经家庭层覆盖 web 行；横幅 URL 恒打 `127.0.0.1`（L161 硬编码）故 URL_RE 健壮，端口覆盖由横幅读取自然吸收 —— 观察，无需改动。
3. **`DSH_TELEMETRY_DISABLED`**：新增环境开关；可选加固项（扩展 spawn env 注入 `DSH_TELEMETRY_DISABLED=1` 可静默会话遥测），是否采纳留待用户决策。
4. **webserver compression**：web profile 开启 gzip level 1；authProxy 透传实体头已兼容 —— 观察。
5. **`SIGTERM` 语义**（profile-boot.ts L224，监督者正常停止 → exit 0）：Windows 端扩展经 taskkill 路径终止，无影响 —— 观察。
6. **可选配置族**（`--trusted-host`/`trustedHosts`/`maxRequestBodyBytes`）：仅非回环/大请求场景相关，扩展 loopback-only 不触及 —— 观察。
