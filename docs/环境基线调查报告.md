## 3. 构建可复现性：沙箱内首次安装为何失败（根因链）

在 DSH 文件沙箱（workspace-write）内直接 `npm install` 的失败链：

1. **npm 缓存写入被拒**：默认缓存 `C:\Users\wangbaikang\AppData\Local\npm-cache` 在 workspace 之外，
   写 `_cacache\tmp` 直接 EPERM（实测 `Set-Content` 该目录亦 Access denied）。
2. **npm 生命周期脚本 spawn EPERM**：`@npmcli/run-script` 以管道捕获子进程输出，
   命中沙箱“管道捕获子进程输出 EPERM”的已知边界（`stdio:'inherit'/'ignore'` 可用，pipe 不可用）。
3. **损坏的依赖树**：两次失败的安装留下**不完整的 `undici-types@6.21.0`**（仅 `agent.d.ts` 0 字节，
   缺 `index.d.ts` 等），导致 `tsc` 报 4 个 `Response` 类型错误（`ok/text/status` 不存在）——
   即《开发报告》“tsc 0 错误”在本环境不复现的直接原因。
4. **同类受影响的无头能力**：`resolvePortPid`（netstat 管道）、`processCommandLine`（PowerShell 管道）
   在沙箱内 `spawnSync … EPERM` → `sim.mjs` 在沙箱内 **6/8 PASS**，其中
   “closing last window stops dsh / registry dsh record cleared” 2 例因 pid 解析返回 null 而失败。
   **属环境差异，非代码缺陷**；正常 Shell 应如文档 8/8 通过（用户已确认：如实记录，不改代码）。

  若未来引入有 postinstall 的依赖，须回到正常 Shell 安装。
