## 〇、一页速览（评审入口——只读本段即可做通过/不通过决定）

### 0.1 这两项功能是什么

1. **P-CHANNEL-SELECT（通道选择）**：dsh 有三个发布通道（`latest`/`next` = rc 稳定系，`alpha` = 最新实验系）。插件第一次启动时弹一个**原生 QuickPick** 让你选「启动哪个通道的 dsh」，选完才启动（先选择通道、后启动dsh）；以后随时可从命令面板 `DSH: 选择 dsh 通道` 改（改选经重启 dsh 生效，不自动重启）。
2. **P-TOKEN（token 适配）**：dsh 0.1.2-alpha.2 起（首个含登录契约的发布版本；alpha 通道当前指向 = alpha.3），网页访问有了登录契约——启动时打印带 token 的 URL，浏览器须凭 token 换 30 天会话 cookie。本设计让插件自动完成这一切：面板经插件内嵌的**本地代理（authProxy）**接入、登录态自动建立（你无需复制 token）；「在浏览器打开」按钮外发带 token 的直达链接。

### 0.2 用户看到什么变化

| 场景 | 现在（0.1.13） | 0.1.14 之后 |
|---|---|---|
| 第一次启动插件 | 按默认通道 latest 直接启动 | 弹 QuickPick 三选一（latest/next/alpha），选后才启动；Esc = 沿用当前值、下次再问 |
| 选 alpha 后的面板 | —（alpha 会话建立不了，面板不可用） | 面板正常可用（登录态由本地代理自动建立） |
| 选 alpha 后点「在浏览器打开」 | 打开即 401 | 打开带 token URL，免登录直达 agent 界面 |
| 继续用 latest/next | 一切照旧 | 一切照旧（逐位零变化，见 0.4 兼容承诺） |
| 设置里看通道 | `latest/preview` 两项，preview 是坏值 | `latest/next/alpha` 三项；旧值 preview 自动按 latest 处理 |

### 0.3 为什么必须这么做（不做的后果）

- **面板直连 token URL 必死，一句话：** dsh 的会话 cookie 是 `SameSite=Strict`——顶层为 `vscode-webview://` 的跨站 iframe 根本不携带它，把带 token 的 URL 直接塞进面板 iframe 也只能加载到壳（index），随后所有 `/api` 数据请求全部 401，面板**结构性不可用**；唯一出路 = 插件在本机回环起 authProxy，由它以服务端身份持有 cookie 并代发（SameSite 不约束服务端到服务端转发）。
- **启动探活必死：** 现有 probe 是裸 `GET /`，alpha 下无 cookie 必 401 → 永不就绪；且连续失败会被既有逻辑误判成「用户关窗停止」（false user-stop **误停**风险）——probe 必须升级 + 401 分流。
- **外部浏览器 401：** 「在浏览器打开」发裸 URL 必 401，必须外发带 token URL（与用户 alpha 手跑样本同路径）。
- **无绕过可谈：** `dsh web` 没有「关闭鉴权」的 flag（仅 `--host --port --trusted-host --no-open`）——适配是必答题。
- **通道选择：** 现配置枚举 `["latest","preview"]` 中 `preview` 根本不是 npm dist-tag（在线查证 E404）——枚举本身损坏；且用户明确要求首启可选（需求原文 §2.1）。

### 0.4 安全承诺

- **registry 不存凭证**：token/cookie 不写 `instance.json`（registry 零新增字段）、不落任何盘上文件——proxy 会话只在内存。
- **日志打码**：插件自写日志面（rlog + panelLog + openBrowser 消息载荷记录范围）token 一律 `token=<REDACTED>` 后落盘；dsh 自身 managed log 保留 banner 原文（dsh 的输出 = 上游 e2e 同款取证数据源，如实声明）。
- **代理仅绑回环** `127.0.0.1` 随机端口；**响应 `Set-Cookie` 一律剥离**——30 天凭据不落 webview 存储。
- **凭证文件只读**：`.credentials.yaml` 只读打开、绝不写回；本轮探针全程零写入零网络。
- **不扩大暴露范围**：上游本就只听回环、全体本机进程本就可达；authProxy 自身无鉴权属**诚实边界**（信任域 = 本机用户权限域，与 managed log 明文 token 同域）——如实声明，不做 proxy 鉴权层（§2.5/§3.8）。

### 0.5 兼容承诺（banner 双形态）

| 契约 | banner | probe | 面板 iframe | openBrowser |
|---|---|---|---|---|
| 旧（< 0.1.2-alpha.2 = latest/next 现值） | 无 token | 裸 GET 200（原样） | 裸 URL 直连（原样） | 裸 URL（原样） |
| 新（≥ 0.1.2-alpha.2 = alpha 现值 alpha.3） | 恒带 token | token-303 探活 | 本地代理 URL | 带 token URL |

- 旧契约路径与 0.1.13 **逐位一致、零回退**；档位判定**按运行中具体 dsh 版本与阈值 V\* = 0.1.2-alpha.2 比较**（用户裁决 2026-09-01：**通道名与 banner 特征均不参与判定**；版本线三方独立证据定案见 EVIDENCE E-VER 组）——next/latest 未来升到 0.1.2-rc/stable 时阈值自动覆盖、零设计变更；banner `?token=` 捕获**保留**为 token 取值数据源（**判定看版本、取值看 banner**）。
- `DshLaunchInfo` 只加第 16 个**可选**字段 `externalUrl`（null = 旧契约），既有 15 字段消费者零破坏；registry/详情卡/状态栏结构零新增破坏性变更。

### 0.7 风险与边界（诚实声明）

| 项 | 边界 |
|---|---|
| alpha 样本量 | 用户手跑 1 次（banner 带 token）+ monorepo 源码/已安装 alpha.3 产物双源取证；版本线三方独立证据定案 V\* = 0.1.2-alpha.2（E-VER）；上游 browser-auth 可能再变——判定按版本阈值 + 判定表矛盾/降级行 + C 路径兜底 |

| authProxy 无鉴权 | 本机任意进程可经代理端口访问 dsh——信任域 = 本机用户权限域（0.4 已声明，属边界事实非缺陷） |
| mtime 择选残留 | 离线边 + 缓存多版本共存时 `pickNewest` 可能按 mtime 选错目录——`pickNewest` 结构性行为，本轮**显式接受**（rlog 留痕缓解），存量修复单列不混入本批（§2.5） |

| 启动时延 | 首启仅一次 QuickPick await（用户交互时间）；proxy 启动 = 本地 listen 毫秒级 + 一次 303 自举往返——启动时延预算不受扰 |

## 二、P-CHANNEL-SELECT 设计（ADR-29）

### 2.1 需求与通道模型核实

- **需求 verbatim（2026-09-01）**：「dsh发布了3种标签，alpha、latest、next，其中latest和next是相同的都是rc版本，alpha是比他俩都新的alpha版本，在插件第一次启动时最好做一个界面能让用户选择启动哪个标签的dsh，用户选择后再启动dsh」。

| dist-tag | 版本（2026-09-01 实测） | 发布 | 语义 |
|---|---|---|---|
| `latest` | 0.1.1-rc.2 | 2026-08-21 | 稳定通道（当前 = rc 版本，**旧契约无 token**） |
| `next` | 0.1.1-rc.2 | 同 latest（同一版本双 tag） | 预发布前瞻（当前与 latest 同值；上游发新 rc 时先于 latest） |
| `alpha` | 0.1.2-alpha.3 | 2026-08-31T16:20Z | 最新实验通道（**含 browser-auth 新契约，§3**） |
| ~~`preview`~~ | — | `npm view @deepseek-ai/dsh@preview` → E404 | **不存在的 dist-tag** |

- 上游家族规则（`scripts/release/families.ts` L353-356 `distTagForVersion`）：alpha/canary prerelease → `alpha`；其余 prerelease（rc）→ `next`；stable → `latest`——**「经 npm 默认」限定**：`distTagForVersion` 对 stable 返回 `undefined`，stable 的 latest tag 是 npm 侧对未显式打 tag 版本的默认行为（families.ts L351-357 + npm 基类 L291 注释），非该函数直接产出。
- **既有配置面缺陷与残留声明（W-1 降低结论口吻后定案）**：`package.json` `dsh.channel` enum = `["latest","preview"]`（L86-94）——① `preview` 非 dist-tag：在线路径 E404 → resolver 视为无版本 → 走回退链或失败；② 离线边 V=null 时 `pickNewest` 按 mtime 择选（`dshResolver.ts` L452-459 区域），缓存同时存在 0.1.1-rc.2 与 0.1.2-alpha.3 目录时可能选中 alpha.3 冒充「preview」。**残留声明**：该 mtime 择选歧义在**合法 channel（latest/next/alpha）+ 离线边 V=null + 缓存多版本共存**时仍可达（如 latest 离线选中 alpha.3 目录）——属 `pickNewest` 结构性行为、非 enum 迁移可消除；本轮**显式接受残留**、不承接一般化修复（存量缺陷修复单列，#68-#79 无项承接），rlog 留痕部分缓解（ADR-13 既有「rlog 声明所选」）。
- 需求拆解：U1 首启判定（`dsh.channelSelected` 未置 → 呈现选择界面）；U2 选择生效（选中 → 写 `dsh.channel` → **之后**启动 dsh——「先选择通道、后启动dsh」时序硬约束）；U3 通道模型（三值 + legacy `preview` 归一）。

### 2.2 ADR-29 决策记录（全条等义移植）

1. **enum 单点迁移**：`["latest","preview"]` → `["latest","next","alpha"]`（default 保持 `latest`）——preview 伪 dist-tag 路径消除（mtime 择选残留另声明，上文）。
2. **legacy 归一**：读到 `preview` → 运行时归一为 `latest` + rlog 留痕（`channel 'preview' is not a published dist-tag; normalizing to 'latest' (ADR-29)`）；**不强制写回用户配置**（保守取舍：设置 UI 中旧值可见、用户可自行改；写回作为可选增强记录不实施）。归一点 = `readConfig`（extension.ts L31 单点）+ `dshResolver` 入口双重防护（防绕过 extension 的无头测试路径直用非法值）。
3. **首启标志**：新配置 `dsh.channelSelected`（boolean，default `false`，scope window）——`false` 即「首次启动/用户未确认过」。**落选 inspect() 法**：`latest` 恰是 default 值，「用户显式选 latest」与「从未选过」无法区分，且对设置同步/便携模式边界敏感；显式布尔标志语义直白、无头可测、天然提供「下次再问」语义（取消 = 不置标志）。
4. **首启 UI = 原生 QuickPick（方案乙）**：`activate()` 内 `new DshRuntime()` 之前同步 `await`——「先选择通道、后启动dsh」时序唯一满足形态；选中写配置后启动、Esc 沿用当前值且下次再问。
5. **重入口命令 `dsh.chooseChannel`**：命令面板随时可改；选择后提示「重启 dsh 后生效」，不自动重启（尊重运行中实例，用户可用既有「重启服务」完成切换）。
6. **runtime/dshResolver/dshProcess 零改动**（channel 早已参数化，spec=`${DSH_PKG}@${channel}` 天然支持三值；ADR-12/13 机制不动）——**范围限定 = 通道选择机制层面**；ADR-30 token 面的 runtime/dshProcess 改动（含 v1.1 判定纯函数落点 dshProcess.ts）见 §四。

**否决项**：甲 panel webview 内选择页（选择须先于 runtime——空 webview 新状态机面 + 新 UI 通道）；丙独立 webview 第三视图（懒渲染时点在启动后 + 常驻膨胀）；inspect() 检测法（default 值歧义）；运行期热切换（dsh spec 启动后不热切）；精确版本钉选（记录为未来可选）；写回归一（设置 UI 保守不强制）。

### 2.3 QuickPick 流程（ADR-29-④，五步）

1. **触发点**：`extension.ts` `activate()` 内、DshRuntime 构造之前（启动链前移点——首启自动拉起与用户手动启动均先过选择）；条件 = `dsh.channelSelected === false`。
2. **items（三选一，文案不含具体版本号字面量——运行期不可知、去硬编码纪律，版本号由 ADR-22 详情卡既有展示面承载）**：
   - `latest` =「稳定通道（rc 版本）——经典启动契约，面板直连可用」；
   - `next` =「预发布前瞻——当前与 latest 相同，上游发布新 rc 时先于 latest」；
   - `alpha` =「最新实验通道——含 browser-auth 新特性，启动后带访问 token、面板经本地代理接入；首次冷缓存下载可能需数分钟」。
3. **语义**：`canPickMany=false`、`ignoreFocusOut=true`、`placeHolder='选择要启动的 dsh 通道（可稍后在设置或命令面板中更改）'`；**选中** → 写 `dsh.channel`（global）+ `dsh.channelSelected=true` → 继续 start 链；**Esc/取消** → 沿用当前配置值（default latest）+ **不置 channelSelected**（下次启动再次询问——显式放弃 ≠ 已选择）+ rlog 留痕。
4. **写配置失败回退**：`update` 抛出 → 捕获 + rlog 留痕 + 沿用旧值继续启动（选择失败不阻塞启动——诚实降级，最坏 = 0.1.13 现行为）。

## 三、P-TOKEN 设计（ADR-30）

### 3.1 browser-auth 新契约（源码级清单，双源同构）

调研对象：monorepo `packages/client/connection/src/browser-auth.ts`（313 行全量复读）+ 已安装 `@deepseek-ai/dsh-client-connection@0.1.2-alpha.3` 产物逐常量同构 + 上游 e2e（`apps/cli/tests/web-auth.e2e.ts`）。

1. **launchToken**：每次 `dsh web` 启动生成 32B 随机 → 43 字符 base64url；per-process `WeakMap` 持有、**不持久化**（browser-auth.ts L20/L52-58）——进程死即失效；
2. **secret 持久层**：`<DSH_HOME>/.credentials.yaml`——重启后旧 cookie 仍有效的根因（E-AU-7：重启换新 token、旧 cookie 有效，e2e L196-197）；
3. **cookie**：`dsh-auth-<hash>`，HttpOnly + SameSite=Strict（非 Secure——本地 http 所需）、max-age 30d（L121-123 + 已安装产物 L684 default 30）；
4. **入口流程**：`GET /?token=<t>` → 校验 → **303 重定向 + Set-Cookie** 种会话（L240-266）；无 cookie `GET /` → **401**（body：`dsh web authentication required; reopen the URL printed by dsh web.`）；
5. **API 全拒**：`/api` 前缀路由统一 `requestRejection` → 401（client/connection L114-127）——无 cookie 时 SPA 一切数据请求必败；
6. **资产公开范围**：仅 index（GET /）经 `authorizeIndex`（frontend-static L88-91）；非 index 静态资源公开；
7. **Host fence**：伪造 `localhost:port` Host 头 → 401（e2e L168-171）——任何代理/转发必须保持 Host 与 socket 目标一致；
8. **无关闭开关**：`dsh web` flags 仅 `--host --port --trusted-host --no-open`（apps/cli/reference/README.md L27/L70/L80）——插件无法要求 dsh 关闭 auth。

**关键定案（任务书前提证伪）**：token 恒随启动 banner 打印、**与 `--no-open` 无关**（banner 恒为 `dsh web: http://127.0.0.1:<port>/?token=<token>`；`--no-open` 仅抑制「opening the default browser」交接行；`printUrl` 与 `noOpen` 独立两个配置位——monorepo web-app L261/L280/L283 + 已安装 lib L35/L211/L213 双源同构）；真机所见无 token banner 实例经 runtime.log 证实均为 channel=latest → 0.1.1-rc.2 旧契约产物（非 alpha）。上游 e2e L94 官方即以 `--no-open` 启动并从 stdout 捕获带 token banner URL——**编程捕获契约成立**。一句话：**无 token banner = 旧契约标记**（已观测样本 ≤0.1.1-rc.2）；特性引入的精确版本线定案 = **V\* = 0.1.2-alpha.2**（rc.2 与 alpha.3 之间仅 alpha.2 一个发布版本、无未分类中间态——EVIDENCE E-VER 组三方独立证据，§3.3 判定表）。

### 3.3 ADR-30 决策记录（全条等义移植）

**核心不变量**：dsh 上游 auth 契约不改（无 flag 可关）、插件只做「会话获取 → 本地代发 → 面板/浏览器可达」；**D3 红线：registry 不存 token**（token 每次启动轮换使持久化无意义 + 缩小泄露面；`instance.json` 零新增字段）。

1. **banner token 捕获（保留，取值数据源）**：`URL_RE` 扩展 token 捕获组（`/\?token=([A-Za-z0-9_-]+)` 形态，**不锚定 43 长度**——防上游改长度即碎，字符类 + 边界判定）；`SpawnedInfo` 增 `authToken: string | null`；旧契约 banner 无 token → null（零回退）。
2. **probe = token-303 探活**（§3.5 全条）；**iframe 必经本地 authProxy**（新纯 Node 模块 `src/authProxy.ts`，§3.4 全条）；**openInBrowser 外发带 token URL**（§3.6）；**契约模式判定 = 版本阈值驱动（v1.1 用户裁决 2026-09-01，替代 v1.0 的 banner 特征检测）**：判定锚 = 运行中具体 dsh 版本与 **V\* = 0.1.2-alpha.2** 的 semver prerelease-aware 比较，**通道名零出现**（判定链与判定表见下）；banner `?token=` 捕获保留为 token 值数据源——**判定看版本、取值看 banner**；**registry 不存 token（D3）+ 脱敏 + managed log 明文如实声明**；**会话来源 T → C 两级**（§3.7）。**未来兼容收益（用户裁决）**：next/latest 未来升到 0.1.2-rc.x / 0.1.2 stable 时 semver 比较自动 ≥ V\* → 阈值自动覆盖、零设计变更。
3. **否决项**：iframe 直连 token URL（方案乙，结构性不可用，正式否决）；要求 dsh 关闭 auth（无 flag）；token 持久化/入 registry（轮换语义 + 泄露面）；cookie jar 维护（303 探活下无必要）；proxy 层 401 语义翻译改写（诚实透传原则）；**按 channel 名判契约模式**（用户裁决 2026-09-01 否决——通道名只决定装哪个版本、不决定代理模式）；**按 banner 特征判契约模式**（v1.0 原定，r5 起被版本阈值判定取代——banner 降为取值数据源，历史决定如实留痕）。

**依据链**：① **版本线定案**：强制 token auth 引入提交 3e24087bfa（2026-08-25）→ 最早包含 tag dsh-v0.1.2-alpha.1（未发布 npm）→ **首个发布版本 = 0.1.2-alpha.2 = V\***（git tag 包含性 + npm 版本线 + alpha.2 行为证据，三方独立证据相互印证——EVIDENCE E-VER 组）；② SameSite=Strict 跨站 iframe 不带 cookie → 直连结构性不可用（/api 全拒）；③ 303 探活免 cookie jar——probe 复杂度不升反降；④ proxy 服务端转发不受 SameSite 约束 + Set-Cookie 剥离 + Host/Origin fence 遵守；⑤ 重启换 token 旧 cookie 有效（E-AU-7）→ proxy 重建即恢复。

**判定链（v1.1 定案；通道名零出现）**：

`dsh.channel（latest/next/alpha——仅决定 spec = ${DSH_PKG}@<channel> 安装哪个版本）→ resolver 安装/复用（ADR-12/13 机制不变，dshResolver 零改动）→ SpawnedInfo.resolved.version = 运行中具体版本（选中目录 package.json 的 version，spawn 前定案；dsh 自身 bin.ts L14-22 亦读同一文件——双端同源单一事实来源）→ judgeContractByVersion(version) 阈值比较（V\* = 0.1.2-alpha.2）→ token 契约：起 authProxy + token-303 probe + externalUrl（token 值 = banner 捕获）｜legacy：直连零变化｜unknown：判定表 #3 行`

- **版本源定案（三案评估，决策记录）**：**(b) 定案 = `SpawnedInfo.resolved.version`**——resolver 按包名+版本读选中目录 `<dir>\node_modules\@deepseek-ai\dsh\package.json`（dshResolver L196-208），三模式恒有值（steady/refreshed/established）；「复用已装缓存」一致性 = spawn 的 binJs 即该目录产物 → 运行中进程版本 ≡ 该 package.json 版本（与 banner token 捕获**零循环依赖**：版本 resolve 时定案、token spawn 后捕获）；runtime 既有 `lastResolved`（runtime L186/L413）承接、`DshLaunchInfo.resolverVersion` 既有展示位升级为判定主源（其「next-launch 辅助源」注释语义由实施同步修订）。落选：**(a) 扩展 `parseSelfVersion`**——结构性无源（双契约 banner 行均不含版本 token，扩展正则无版本可提取；且首行契约系详情卡 pinned 展示行为，E-VR-5）；**(c) registry/instance.json**——无 version 既有字段（DshRecord = pid/port/managedBy/startedAt/launchMode），新增 = schema 面扩张 + 写入时机晚于判定点；meta.knownVersion 同落选（channel 键 + TTL + refreshed 漂移，非 per-launch 事实）。附带收益（E-VR-7）：离线边 `pickNewest` 误选目录场景下判定输入 = 实际 spawn 版本 → **判定自校正**，§2.1 mtime 择选残留的后果从「面板坏」降为「通道语义偏差 + 行为正确」。

| R7 | **WS upgrade 同栅栏**：`/api/remote.mux` upgrade handler 同调 `requestRejection(req)`（`gateway/index.ts` L211-228，path 常量 `stream-protocol.ts` L6）；webserver upgrade 表精确匹配、未命中连接直接关闭——**无栅栏旁路**。浏览器 WS handshake 恒带 Origin（RFC 6455 浏览器行为）→ 与 HTTP 同一 R4 重写规则、无需分支 | E-TRUST-3 |

- **三方数据流时序图**：引用承接文档 `docs/archive/dsh-alpha适配分析与方案.md` §3.6 L174-201 mermaid（token 获取 → URL 构造 → iframe 加载 → POST/WS 全链），按本轮四点差异对照：① cookie 由 proxy 服务端持有注入；② 响应 Set-Cookie 剥离（止于 proxy、不出 proxy）；③ 转发头 Host/Origin 均重写为上游 authority；④ 上游 401 → 单次重取 + ×3 error 终态（§3.5）。

### 3.5 probe 升级：token-303 探活 + 401 分流（全条）

- **token 契约档（版本 ≥ V\*，判定见 §3.3 判定表）**：probe = `GET http://127.0.0.1:<port>/?token=<t>`（`redirect: 'manual'`）期待 **303**——303 = 服务活 + token 有效，**无需 cookie jar**（不跟随重定向）。
- **401 语义分流**：401 = 服务活但会话失效（token 轮换/失配）→ 与「进程死」**分流**：不触发崩溃回退计数，触发**会话重取**（re-capture banner token + proxy 重建）。
- **会话重取边界（W-3 定案）**：重取 = **单次**（不设重取循环）；重取后下一 tick 仍 401 → 计入**独立的 401 计数**（与崩溃回退计数、ADR-21 用户停止判定**均隔离**），连续 **×3 → error 态终局**（面板呈「会话失效——请重启服务」指引，**不自动重拉**）；重取动作 rlog 留痕。
- **误停消除**：`probeTick`（runtime L611-659）适配——401 **不计入** ADR-21 用户停止判定路径、不计崩溃回退（§3.2 影响范围第 2 行的 false user-stop 风险就此消除）。
- **旧契约档（版本 < V\*）**：既有裸 GET 200 形态零回退。
- **档位判定（v1.1）**：按版本阈值（`judgeContractByVersion(resolved.version)`，V\* = 0.1.2-alpha.2，§3.3 判定表）；banner 特征不参与判定（`?token=` 仅作 token 值数据源）——判定锚 = 具体版本（用户裁决），通道名与 banner 特征均退出判定层。

### 3.6 openInBrowser 外发 + 日志脱敏纪律（全条）

- `openInBrowser` 改用 `runtime.externalUrl`（带 token 的 banner 原始 URL——外部浏览器首访直达登录态，与用户 alpha 手跑样本同路径；无 token = 旧契约裸 URL 原样）；`DshLaunchInfo` 新增**可选第 16 字段** `externalUrl?: string`（null = 旧契约——既有 15 字段消费者零破坏）。
- **rlog 脱敏**：plugin 自写 runtime.log 中 token 一律 `token=<REDACTED>`（正则替换后落盘）；**脱敏范围枚举完整 = rlog + panelLog + openBrowser 消息载荷记录范围**（NOTE-5）。
- **managed log 保留 token 原文**：dsh 自身输出 = 上游 e2e 同款取证数据源，插件不干预不重写（断言「不重写」）。
- **明文安全声明**：token 每次启动轮换（泄露窗 = 单次启动会话；30d cookie 由本机用户权限域保护；`.credentials.yaml` 0600 先例）——明文入 managed log 属上游既有行为（banner 本身即明文），插件不新增持久化、限窗可接受、如实声明。

### 3.7 C 路径与 P-TOKEN-PROBE-1 实测结论（2026-09-01，已批准已执行）

- **C 路径定义**：T（banner token）失效态的会话兜底——外部实例接管（无插件 banner 捕获机会）或 banner 丢失时，从 dsh 凭证文件 `<DSH_HOME>/.credentials.yaml` 读取持久 secret，按上游同一算法本地生成会话 cookie（承接文档 §3.4 原案；**只读，绝不写回**）。
- **P-TOKEN-PROBE-1 实测（2026-09-01 执行；用户批准；只读、零写入、零网络）→ 三态结论：FEASIBLE**（v2.20「C 路径本轮未实测」就此定案为实测通过）：
  1. **字段结构吻合**：`records['client-connection/browser-session'] = {kind:'grant', payload:{version:1, secret:<43 字符 base64url>}}`——与 `browser-auth.ts` L12（record 键）+ L87-98（StoredSecretPayload 校验）逐字段一致；secret 解码 32 字节、canonical round-trip 成立；文件 270B/11 行，结构 = `version/refs/records` 三节（与 credentials-local `parseRecords` `<scope>/<id>` 键格式一致）。
  2. **cookie 名方案复核**：`dsh-auth-` + base64url(sha256(authority))（L106-108）——样例 authority（假端口 127.0.0.1:40001）实算 52 字符形态（9 前缀 + 43 base64url），与源码同构。
  3. **值计算可离线复算**：按 L129-132 本地生成 `v1.<body>.<sig>`（32B HMAC-SHA256 → 43 字符签名段）并复刻 L289-302 验证链——内存内 shape/HMAC/payload/时间窗四项全过、同 issuedAt 确定性重新生成逐字节一致、Cookie 头提取 round-trip 成立。**本地生成输入仅 = 文件 secret + authority（`127.0.0.1:<dshPort>`，与 R3 Host 重写同值天然对齐）+ 本地时钟——零服务器交互**。
  - 探针细节行级记录：EVIDENCE.md E-PROBE 组（E-PR-0…6，含已安装 alpha.3 产物常量同构双源核对 E-PR-6）；产出全程仅字段名/结构/长度/公钥派生哈希，**secret 原文零出现**。
- **诚实边界**：本探针为「离线复算面」验证——真实实例上游是否接受本地生成 cookie（需向运行中实例发请求）不在授权范围（零网络约束），真机最终判定归 RV-15-4 两分支判据（§7）。
- **对实施面的影响（事实演进、技术决定零变更）**：#69 C 路径从「仅接口留位待核实」升为「随 0.1.14 实施」；#73 前置「探针先行执行」已满足；#74 核对项「P-TOKEN-PROBE-1 结论与 C 路径实现一致性」照常执行。

### 3.8 安全与诚实声明

- token 模型属上游设计，插件仅适配不重定义；不新增持久化秘密；authProxy 端到端行为实施轮以 PP-8 无头 mock 预验；版本线样本 = 0.1.1-rc.2 / 0.1.2-alpha.2 / alpha.3（E-VER 三方独立证据定案），上游可能再变——判定按版本阈值 + 判定表矛盾/降级行兜底是防变的第一道；本设计不宣称覆盖 browser-auth 全部边界（以 e2e 已证行为 + 已读源码为限）。
- **authProxy 无鉴权诚实边界（NOTE-2 定案）**：proxy 本身无鉴权——本机任意进程可经 `127.0.0.1:<proxyPort>` 无 token 访问 dsh；信任域 = 本机用户权限域（与 managed log 明文 token 同域），且不扩大上游暴露范围（上游本就监听回环、全体本机进程可达）——如实声明，属边界事实非缺陷，不做 proxy 鉴权层（§二 不做什么；如需更强边界属未来独立立项）。

## 七、验证判据（等义移植）

### 7.1 无头自动化（PP-8 / PU-9；`node scripts/sim.mjs`，先 `npm run compile`）

**PP-8-1 token 捕获契约**：mock banner `dsh web: http://127.0.0.1:<P>/?token=<43字符base64url>` → `SpawnedInfo.authToken === <token>`（URL_RE token 组捕获；port 捕获不受扰——同 banner 双解析断言）；旧形态 banner（无 `?token=`）→ `authToken === null` 且 port/URL 解析逐位回退（零回退）；malformed token（空/含 `&`）→ null + 不抛异常（诚实降级）。

**PP-8-2 authProxy 契约（mock 上游三态 + Origin-fence 断言组）**：① mock 上游 `GET /?token=<t>` → 303 + `Set-Cookie` → proxy 首次自举成功、后续转发请求带 cookie 头、Host 头 = `127.0.0.1:<upstreamPort>`（Host fence 断言）；② **Origin-fence 断言组（本地起 authProxy + mock 上游 stub，验证 Origin 重写与不重写两种结果）**：mock 上游按上游栅栏最小语义判定（`origin === host` 才 200、失配 403——api-request-trust.ts L114 同判）；带 `Origin: http://127.0.0.1:<proxyPort>` 的请求经 proxy 转发后 Origin === Host === 上游 authority → 200（**重写断言**）；对照组 = mock 上游直收未重写 Origin（proxyPort 值）→ 403（**「不重写必 403」的上游语义钉入测试，防门控逃逸/无头绿真机红**）；无 Origin 请求 → 转发后仍无 Origin → 放行（**不补断言**——L112 缺失放行）；WS upgrade 请求带 Origin → 同规则重写后 101（**同规则覆盖断言**）；bad Origin + 无 cookie → 403 非 401（**栅栏先于 cookie 次序断言**——rpc-host.ts L95-98）；③ 上游 401 → proxy 原样透传 401（不吞不改断言）；④ `stop()` → 端口释放（rebind 断言）；**Set-Cookie 剥离断言**（上游 303 响应的 Set-Cookie 不到达客户端）；token 不落盘断言（proxy 生命周期内零文件写入）。

**PP-8-3 probe 双形态与 401 分流（形态选择 = §3.3 版本判定结果）**：token 契约档（版本 ≥ V\*）→ probe = `GET /?token=<t>`（`redirect:'manual'`）期待 303 判就绪（不跟随重定向断言）；401 → 会话重取分流（**不**计入崩溃回退计数、**不**进入 ADR-21 用户停止判定路径——false user-stop 消除断言；**重取边界断言**：单次重取 + 独立 401 计数，连续 401 ×3 → error 态指引、无循环重取）；旧契约档（版本 < V\*）→ 裸 GET 200 + `__DSH_BOOT__` 原样（既有断言零回退）。

**PP-8-4 脱敏与不落盘**：rlog token 一律 `token=<REDACTED>`（mock 场景断言落盘内容零 token 原文；脱敏范围枚举 = rlog + panelLog + openBrowser 消息载荷记录范围）；`instance.json` 写入载荷无 token/externalUrl 值字段（D3 字面级断言）；managed log 保留原文（dsh 自身输出不干预——断言不重写）。

**PP-8-5 全族回归**：PV/PW/PI/PP-1..7/PU 零回退（token 组为 URL_RE 增量捕获、probe 旧形态逐位、iframe 裸 URL 档原样）。

**PP-8-6 版本阈值判定（v1.1 新增；§3.3 判定表单测）**：① 阈值边界与 semver 序（`judgeContractByVersion` 纯函数导入直测）——`'0.1.1-rc.2'` → legacy（不起代理）；`'0.1.2-alpha.1'` → legacy（阈值 = alpha.2；该版本未发布 npm，若出现即落判定表 #4 行）；`'0.1.2-alpha.2'` → token（**含等号**）；`'0.1.2-alpha.3'` → token；`'0.1.2-rc.1'` / `'0.1.2'` / `'0.1.3-alpha.1'` → token（**未来版本自动覆盖断言**——next/latest 升级零设计变更）；prerelease 排序正确性（`0.1.2-alpha.10` > `0.1.2-alpha.9` 数值序、`rc` > `alpha`）；malformed（`'foo'`/`''`）→ unknown 不抛异常；② 不可读（null）→ unknown → 判定表 #3 行：mock adopt 会话（无 SpawnedInfo）→ 旧契约直连起手 + probe 401 → 401 分流 → C 路径会话建立 + proxy 升级（承接 PP-8-2/PP-8-3 mock 形态，零新增机制断言）；③ 矛盾态合成 banner：带 token banner + `version='0.1.1-rc.2'` → #4 行处置（token 侧 + rlog WARN 双事实）；无 token banner + `version='0.1.2-alpha.3'` → #5 行处置（版本侧维持 + C 兜底 + WARN）；④ latest 形态回归：旧 banner（无 token）+ `'0.1.1-rc.2'` → 逐位旧路径（与 PP-8-5 呼应）。无头可执行性自查：纯函数导入直测 + mock deps（E-SIM 先例——纯 Node 模块直测形态同 PU-9/PP-8-2）+ mock 会话装配——全组无 vscode 耦合阻塞点。

**PU-9 通道模型与首启选择（全组无头可判——断言对象 = `channelSelect.ts` 纯模块导入直测 + mock deps/config store）**：
① **归一三态**（`normalizeChannel` 纯函数直测）——`'preview'` → `'latest'` + 归一标记（rlog 断言）；`'latest'/'next'/'alpha'` 透传；非法值（如 `'foo'`）→ `'latest'` + 留痕（不抛异常）；
② **首启判定**（`runFirstLaunchChannelSelect` mock deps 直测）——`channelSelected=false` → 触发 QuickPick（mock pick = `'alpha'`）→ 断言写 `dsh.channel='alpha'` + `channelSelected=true` 后才返回 `selected:true`（**mock deps 记录调用序：write 先于 runtime 构造回调——先选择通道、后启动dsh顺序断言无头可构造**）；mock pick = 取消（undefined）→ 断言 channel 不变、`channelSelected` 仍 false、`cancelled:true`（下次再问）；mock 写配置抛错 → 沿用旧值继续启动 + rlog 留痕（`writeFailed:true`，诚实降级断言）；
③ **enum 契约静态断言**——`package.json` `dsh.channel.enum` === `['latest','next','alpha']`、`dsh.channelSelected`（boolean, default false）与 `dsh.chooseChannel` 命令注册存在（字面量扫描）；
④ **回归**——PU-1…8 零回退（channel default `latest` 路径不受扰）。

### 7.2 真机 / 普通终端项（RV-15 族；需真实 VSCode，由用户/编排者执行判定）
