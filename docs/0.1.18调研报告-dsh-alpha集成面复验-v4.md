## 一、目标/背景分析

dsh 上游在本轮取证窗口内（2026-09-02 → 2026-09-08）发布了三个新版本：0.1.2-rc.1（rc 稳定线，latest/next 现指向）、0.1.3-alpha.1、0.1.3-alpha.2（alpha 实验线现指向）。本扩展（v0.1.16）通过 npm dist-tag 通道模型管理 dsh 运行时，并通过版本阈值 V\* = 0.1.2-alpha.2 决定 token 契约（authProxy + token-303 探活 + 带 token 外链）与旧契约（直连）的档位。

本轮要回答的问题：

1. **增量变化面**：alpha.5 → 0.1.3-alpha.1/alpha.2 的全部变更中，哪些落在扩展的 8 个集成面契约上？
2. **发布形态**：npm 产物是否延续 0.1.2-alpha.5 的「薄 CLI + 依赖包拆分」形态（v3 O-3 例行核对）；0.1.3-alpha.1 是否真实可安装。
3. **通道位移**：latest/next 从 0.1.1-rc.2（旧契约）升到 0.1.2-rc.1（≥V\*，token 契约）对扩展运行时行为意味着什么。
4. **版本阈值**：V\* = 0.1.2-alpha.2 是否需要因 0.1.3 线更新。

### 2.8 npm dist-tag 现值与通道模型 — 与通道模型一致（通道现值位移，行为注记）

- 实测：`alpha=0.1.3-alpha.2`、`latest=0.1.2-rc.1`、`next=0.1.2-rc.1`。上游发布脚本 `families.ts` 的 `distTagForVersion` 全区间未触碰（HEAD 漂移仅 `members()` 跳过 private 包）——通道模型 A6 语义不变。
- **通道现值位移（本轮关键事实）**：latest/next 从 0.1.1-rc.2（旧契约）升为 0.1.2-rc.1——**latest/next 首次进入 ≥V\* 区间**。按 0.1.14 判定表 #1 行（`≥ V\*（含 0.1.2-rc.x）→ token 契约`），扩展对 latest/next 会话自动切换为 authProxy + token-303 探活 + 带 token 外链——**设计内自动覆盖，零代码变更**（0.1.14 逐字出处：判定表 #1 行明文「≥ V\*（含 0.1.2-alpha.2/3 与未来 0.1.2-rc.x / 0.1.2 stable / 0.1.3+——semver 自动覆盖）→ token 契约」；§3.3 决策记录明文「next/latest 未来升到 0.1.2-rc.x / 0.1.2 stable 时 semver 比较自动 ≥ V\* → 阈值自动覆盖、零设计变更」）。rc.1 产物的契约锚点抽查全命中（§三），且 alpha.5→rc.1 发布提交之间核心契约文件零 diff（probe-log §11）。
