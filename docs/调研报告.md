# DSH 封装为 VSCode 插件（dsh-vscode-agent）——调研报告 v4

> 版本：v4（按用户决策更新）· 日期：2026-08-21
>
> **v4 相对 v3 的变化**（用户拍板四项决策，并补齐相应防护）：
> 1. **面板**：启动后**自动展开右侧边栏**显示 DSH 面板；
> 2. **外部实例**：最后窗口退出时**也尝试关停**（连接时接管其 pid，含误杀防护）；
> 3. **端口**：托管**默认固定 3080**（稳定性优先，接受占用浏览器默认端口的代价并文档化）；
> 4. **版本**：**每次启动自动检查 latest**（离线时回退 npx 缓存版本）；
> 5. 新增：**第一窗口判定原子锁**（消除双窗口同时启动竞态）、**pid 复用校验**（防误杀）、**启动路径（含离线回退）**。

---

## 1. 背景与目标

将 [DeepSeek Harness](https://github.com/deepseek-ai/deepseek-harness)（DSH）封装为 VSCode 扩展，以**右侧边栏内嵌面板**形式运行 DSH Web UI。

### 1.1 需求复述（v4 更新）

| # | 需求 | 说明 |
|---|---|---|
| 1 | 离线安装 | 扩展 `.vsix` 离线安装；dsh 不打进 VSIX，由 npm/npx 托管（首次现装、升级走 npm） |
| 2 | 薄壳定位 | 扩展是宿主包装器：启动/复用 `dsh web`、内嵌 Web UI，不 fork、不打包前端 |
| 3 | 面板位置 | 右侧边栏（auxiliary bar）独立视图；**启动后自动展开显示** |
| 4 | 生命周期 | dsh 随 VSCode 应用级仲裁：第一窗口启动 / 后续窗口复用 / 非最后窗口不停 / **最后窗口退出同步关停（含外部实例接管）** |
| 5 | 并发复用 | dsh 已启动（含浏览器/npx 外部实例）→ 直接访问 `127.0.0.1:<port>` |
| 6 | 参考 | 本地源码 `D:\projects\deepseek-harness`；`D:\projects\dsh-desktop`；本机 VSCode 1.134.0 |

## 3. 关键调研结论（源码级）

### 3.1 DSH 侧（本地源码，已实证）

| 事实 | 源码位置 |
|---|---|
| `dsh web` = `--profile web`；参数族 `--host 127.0.0.1`（`0.0.0.0` 硬拒）、`--port <n>`（0=OS 分配）、`--no-open`、`--trusted-host` | `apps/cli/src/{args,bin}.ts`、`packages/bundle/web-app/src/startup.ts` |
| **默认端口 3080** | `packages/boot/cmdline/src/index.ts` |
| 启动打印 `dsh web: http://127.0.0.1:<port>` | `packages/bundle/web-app/src/index.ts:253-268` |
| `/api` browser-trust 栅栏（回环放行、cross-site 拒） | `packages/client/connection/src/api-request-trust.ts` |
| 浏览器传输 = HTTP RPC + **WebSocket 双事件流**（`/api/events.mux`、`/api/events.host`） | `packages/client/connection/src/client/web-api-client.ts`、`websocket-downlink.ts` |
| 预留宿主接入点 `__DSH_TRANSPORT__`（本方案不需要） | `packages/client/connection/src/client/index.ts` |
| 空 DSH_HOME + 已装 CLI 可完全离线 boot（双锚点 + heal fallback） | `apps/cli/src/profile-boot.ts` 等（v1 已实测） |

### 3.2 VSCode 侧

- **右侧边栏 = auxiliary bar**：`viewsContainers.auxiliarybar` + `views.<容器>` + `registerWebviewViewProvider`；workbench 源码确认 `ViewContainerLocation=2=auxiliarybar`、`workbench.parts.auxiliarybar`。
- **WebviewView**：隐藏时 iframe 释放、可见时 `resolveWebviewView` 重建；`retainContextWhenHidden` 官方不推荐；DSH 页面自动重连，无碍。
- **官方 iframe 范式**（simple-browser）：`<iframe sandbox="allow-scripts allow-forms allow-same-origin allow-downloads">` + CSP `frame-src http://127.0.0.1:*`；桌面版可用。
- **多窗口/进程模型**：每窗口独立 extension host（`process.pid` 作窗口标识）；窗口关闭时 `deactivate()` 不保证调用（[#47881](https://github.com/microsoft/vscode/issues/47881)、[#567](https://github.com/microsoft/vscode/issues/567)）→ 清理必须放 `process.on('exit')`（同步）；扩展间无官方跨实例 API → 自建注册表协调。

| 维度 | A：自建 WebviewView（auxiliary bar） | B：复用内置 Simple Browser |
|---|---|---|
| 右侧边栏 | ✅ 原生容器 | ❌ 只能开 editor 区 tab |
| UI/状态控制 | ✅ 工具栏/进度/错误/状态栏/徽标 | ❌ 固定地址栏 + Focus Lock |
| 生命周期接管 | ✅ 完整（含应用级仲裁） | ❌ 无法感知 |
| 结论 | ✅ 唯一满足约束 | 兜底 |

## 6. 运行时与生命周期设计（v4）

### 6.1 启动路径（每次启动自动检查版本，用户决策）

```
扩展激活（onStartupFinished）
  ├─ 读实例注册表 %LOCALAPPDATA%\DshVscode\instance.json
  │    └─ dsh 存活？（pid 校验 + 端口探测双重校验）
  │         ├─ 存活 → 连接模式：登记本窗口；若 dsh.pid 缺失（外部实例）→ 接管 pid（§6.3.2）
  │         └─ 不存活（僵尸）→ 清理记录，继续 ↓
  ├─ 探测 3080：已被 DSH 占用（GET / 含 __DSH_BOOT__）→ 连接模式 + 接管 pid，登记窗口
  ├─ 否则（第一窗口路径，原子锁仲裁，§6.3.1）：
  │    ├─ 版本决策：registry 可达 → npx 解析 @deepseek-ai/dsh@latest；不可达/失败 → 缓存版本
  │    ├─ spawn：node <npx-cli> --cache %LOCALAPPDATA%\DshVscode\npx-cache -y @deepseek-ai/dsh@<ver>
  │    │         web --host 127.0.0.1 --port 3080 --no-open
  │    ├─ 端口解析（stdout "dsh web: http://…"）→ HTTP 就绪探测 → 写注册表（managedBy: extension）
  │    └─ 端口 3080 被非 DSH 占用 → 回落 --port 0（注册表记录实际端口）
  └─ 自动展开右侧边栏：executeCommand('workbench.view.extension.<containerId>')
```

### 6.2 端口策略（用户决策：默认固定 3080）

- 托管默认固定 3080：端口稳定，**崩溃重启端口不变 → 其他窗口无需刷新**（消除了随机端口的漂移广播复杂度）；浏览器/npx 默认端口一致，复用探测简单。
- **代价与文档化**：扩展先启动会占住 3080，之后浏览器 `dsh web`（默认端口）会 listen 失败——文档明示"浏览器中请用 `dsh web --port 0` 或改端口"，并提供配置 `dsh.port` 调整。
- 3080 被非 DSH 占用 → 回落随机端口（注册表记录，其他窗口按注册表刷新）。

### 6.3 应用级生命周期仲裁（v4 更新）

#### 6.3.1 第一窗口判定（原子锁，消除启动竞态）

- 激活路径上：无 dsh 记录 → 以 `fs.open(startup.lock, 'wx')` **原子独占创建**启动锁（含 pid）。
- 抢到锁 → 走第一窗口路径（§6.1 版本决策/spawn）；释放锁（写注册表后删除）。
- 未抢到锁（其他窗口正在启动）→ **轮询注册表**等 dsh 就绪（≤ 60s）→ 转连接模式。
- 启动锁崩溃残留：锁内 pid 校验，失效即删除重试。

#### 6.3.2 dsh 记录与 pid 接管（用户决策：外部实例也关停）

- 注册表结构（`%LOCALAPPDATA%\DshVscode\instance.json`，原子写）：
  ```jsonc
  {
    "dsh": { "pid": 12345 | null, "port": 3080, "managedBy": "extension" | "external", "startedAt": "…" },
    "windows": [ { "app": "Code", "pid": 65432, "startedAt": "…" }, … ]
  }
  ```
- **托管模式**：spawn 后立即记录 dsh pid（`managedBy: "extension"`）。
- **连接模式（外部实例）**：连接成功后**立即接管 pid**——枚举 3080 监听进程（`netstat -ano` 解析）+ **校验进程命令行含 dsh 特征**（`@deepseek-ai/dsh` / `--profile web`），记录 `managedBy: "external"`；枚举/校验失败 → `pid: null`（退出时重试，仍失败则**不关停**，安全侧）。
- **关停判定**（`process.on('exit')` 同步钩子）：
  1. 从 `windows` 注销本窗口（按 app + pid）；
  2. 注销后 `windows` 为空（全局，不区分 app）→ 关停 dsh；
  3. 关停前**最终校验**（防 pid 复用误杀）：dsh.pid 仍存活 + 仍监听注册表端口 + GET / 仍含 `__DSH_BOOT__` → 三者全过才 `spawnSync('taskkill', ['/PID', pid, '/T', '/F'])`；否则不杀（安全侧）。
- 全局窗口计数不区分 app：stable 与 Insiders 窗口计入同一 `windows`，避免"一个 VSCode 应用关完就杀、另一个还在用"的误杀。

#### 6.3.3 状态机（v4）

| 事件 | 行为 |
|---|---|
| 第一窗口打开 | 原子锁仲裁 → 版本决策 → 托管启动 dsh → 写注册表 → 自动展开面板 |
| 后续窗口打开 | dsh 存活 → 连接 + 登记；外部实例 → 接管 pid |
| 关闭非最后一个窗口 | 仅注销；**不停 dsh** |
| 退出 / 关最后一个窗口 | 注销 → 计数空 → 最终校验 → 关停 dsh（含外部接管实例） |

### 6.4 版本升级（用户决策：每次启动自动检查 latest）

- 每次走第一窗口路径时：registry 可达 → `npx … @deepseek-ai/dsh@latest`（自动检查并更新）；**不可达/解析失败 → 直接跑 npx 缓存中的最近版本**（`--prefer-offline` 语义），不阻塞启动。
- 提供命令「DSH: Update Runtime」手动强制更新 + 重启 dsh；`dsh.channel` 可锁版本（latest/preview/固定）覆盖自动检查。
- 版本变化（重启后 dsh 进程替换）→ 注册表记录新 pid，其他窗口按注册表刷新面板。

## 7. 风险与注意事项（v4 更新）

| 风险 | 等级 | 说明与缓解 |
|---|---|---|
| **固定 3080 占用浏览器默认端口**（用户选择） | 中 | 文档明示"浏览器用 `dsh web --port 0`"；`dsh.port` 可改；3080 被非 DSH 占用时自动回落随机 |
| **外部实例误杀**（接管 pid 引入） | 中 | 三重防护：接管时命令行校验；关停前 pid 存活 + 端口监听 + `__DSH_BOOT__` 复查；任何一步失败则不杀 |
| pid 复用（进程退出后 pid 被新进程占用） | 低 | 关停前最终校验（上一条）覆盖 |
| 双窗口同时启动竞态 | 低 | 原子启动锁 + 轮询等待 |
| 每次启动自动检查的网络依赖 | 中 | 离线/失败回退 npx 缓存版本，不阻塞启动 |
| 首次启动需联网（npx 现装） | 中 | 明示文档；`dsh.command` 指本地 dsh 可完全离线 |
| EH 崩溃 → 注册表僵尸 | 低 | pid 校验清理；dsh 孤儿化由端口探测接管 |
| WebviewView 隐藏重建（iframe 重载） | 低 | dsh 进程独立；页面自动重连；可选 `retainContextWhenHidden` |
| 浏览器正用同一外部实例时被 VSCode 最后窗口关停 | 低 | 用户决策接受（"随 VSCode 走"语义）；文档提示 |
| 多 VSCode 应用并存（stable+Insiders） | 低 | 全局窗口计数避免误杀；注册表按 app 记录 |
| 注册表并发写/损坏 | 低 | 原子 rename + 重试；损坏即重置 |
| vscode.dev 外部 iframe 被禁 | 低 | 桌面版不受影响 |

## 8. 结论与下一步

**结论**：v4 = 右侧边栏 WebviewView（auxiliary bar，自动展开）+ 固定 3080 同源 HTTP/WS 直连 iframe + npx 托管运行时（每次启动自动检查、离线回退）+ 应用级生命周期仲裁（注册表 + 原子锁 + 接管外部实例 pid + 三重防误杀校验 + 最后窗口关停）。

**下一步**：
1. 搭建扩展工程（package.json 含 `viewsContainers.auxiliarybar`、tsconfig、vsce、调试配置）；
2. 实现最小可用版：启动路径（版本决策/npx/离线回退）+ 生命周期仲裁 + WebviewView 面板 + 自动展开 + 自动启动；
3. 本机联调验证：多窗口场景（第一窗口启动/二窗口复用/关一窗口不停/关最后窗口停）、外部 3080 实例复用与接管、npx 冷启动与离线回退；
4. 增强项：状态栏、安装进度、日志落盘、优雅关停（移植 dsd-side）、「DSH: Update Runtime」。
